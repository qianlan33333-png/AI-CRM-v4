# 支付方式开关设计核对

Product Design 使用：index → user-context preflight → get-context → audit，依据既有编辑页确定默认控件与新增位置。本次是现有生产项目内的小范围设置扩展，未新建原型或设计系统。

1. 普通商品现有售卖信息：已捕获当前已登录页面（01-sale-reference.png），白色卡片、两列字段、分销复选框、保存当前维度正常可见。以同壳与现有复选框为视觉依据。
2. 普通商品候选售卖信息：本地合成真实 Host 页面默认勾选「支持支付宝支付」，关闭后提示「仅支持微信支付」（02-ordinary-disabled.png）；控件在售卖信息内，原表单与保存动作保留。
3. 周期商品候选售卖信息：同一原生复选框默认开启，提示双支付（03-period-enabled.png）；关闭提示仅微信（04-period-disabled.png），未出现第二表单壳或布局遮挡。

检查视口：1613×1002。普通商品参考与候选沿用既有间距、字体、色彩、字段和保存按钮；两类新增控件状态及文本清晰。键盘语义使用原生 checkbox、关联 label 和 aria-describedby；未据截图宣称全面无障碍合规。

截图包含实际观察到的当前表单状态；候选页面只用本地隔离合成数据，浏览器切换开关未提交到生产。保存与回读依赖真实 PostgreSQL Host 合同及 serializer 测试，不能由截图替代。

限制：真实 Provider 付款、生产管理员新开关保存与付款页读回仍未验证，Linux 必需浏览器旅程由唯一发布指挥台完成。

本次范围内设计核对：通过。
