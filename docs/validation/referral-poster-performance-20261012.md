## 1000用户/10秒隔离负载

本机macOS、PostgreSQL16.13、GOMAXPROCS=2、共享连接池上限10；1000个不同可信测试actor已有参与资格，邀请与配置并行，随后请求3个轮换的冷底图。真实Referral HTTP与数据库业务调用；仅测试会话解析器模拟身份，不调用OAuth/Provider。

| 指标 | 实测 |
|---|---:|
| 成功 | 988 / 1000，98.8% |
| 明确繁忙 | 12 / 1000，1.2%，不计成功 |
| 其他失败 | 0 |
| 总旅程P95（包含繁忙） | 4.987 ms |
| 最大时长 | 130.518 ms |
| 原图快照读取/压缩 | 3次，3张各一次 |
| Go峰值堆 / 进程峰值RSS | 51.9 MB / 88.3 MB |
| DB连接获取累计耗时 / 取消获取 | 10.462 ms / 0 |
| 图片传输量 / 回环吞吐 | 779556000字节 / 624 Mbps |
| 订单+登录读取，空载 | 100次，0错误，P95 0.324ms |
| 订单+登录读取，负载期间 | 199次，0错误，P95 1.230ms |

订单/登录探针在同连接池中实际调用Order.Get、Access.SessionByTokenDigest和UserByUsername，数据为独立schema的合成订单与账号；不等同于完整安装包登录/订单UI旅程。原图快照SHA读回保持不变。该负载测试显式要求本地`aicrm_poster_perf_`数据库，未登记为无需环境即可通过的普通检查。

冷启动争用给出繁忙是预期负载保护，不能描述为100%生成成功。此结果证明本机应用/DB链路，不证明生产带宽。1000用户10秒每人下载789024字节约需631 Mbps纯图片出口；需在目标Linux/网络环境检查，若实际出口不足，再制定最小CDN接入方案。

## 未验证与发布边界

- Linux 2核2GB的最终同包预发、生产实际出口、安装包相关旅程和认证读回交给唯一发布工作台。
- 微信iOS/Android长按保存、保存后画质/完整码区/真机扫码、真实个人邀请归因尚未验证。不能以HTTP、排队、Mock、软件解码代替。
- 本候选仅改公共海报生成链路；后台未改。基线完整admin前端测试因未物化的既有`web/src/admin/sections/qr`入口不能构建；公共旅程单独编译真实公共源码，不把后台检查算通过。
- 无新增生产表/迁移/队列/Provider写入/云服务/Redis/活动锁改造。OneID、邀请签发、支付及归属机制不改；仅测试schema应用既有迁移及合成数据。
- 用户已授权画质、开发、隔离验证及候选交付，尚无本范围生产部署授权。本任务不安装共享预发或生产。
