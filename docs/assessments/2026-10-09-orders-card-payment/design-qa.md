# Product Design 验收：卡包查看与继续支付

选定目标为本轮用户图二的发票详情与 V4 现有订单/商品支付页。主按钮直接打开图三所示的微信原生卡券；颜色、字体、间距和白色圆角卡片沿用当前页面。无新增图标或素材。

2026-10-09 在真实挂载的候选 TypeScript/CSS 和 Go 模板 HTML 上，用 Codex 浏览器操作验证 390×844、320×740：

- 发票详情显示已出票、金额、交易单号、发票号和卡包交付状态。点击“查看发票”调用 `openCard`，无外部 PDF 导航。实际页面检查发现按钮宽度变小，已修为整行蓝色按钮并重新截图。
- 320 宽度下订单状态栏、长编号换行、详情与按钮可见，无水平溢出；实测 document scrollWidth 等于 viewport width。
- “待付款 → 继续支付”进入原商品付款页，恢复冻结名称与 ¥88.00，而非当前目录 ¥199.00；支付方式锁定，隐藏重新填写联系地址及优惠券的字段。
- 页面载入只读取原订单。点击继续支付才调用原收银台；模拟取消后保持原金额和原订单，可再次继续支付。浏览器请求记录无 POST、新订单创建或优惠券读取。

边界：本地数据与微信桥均为明确标注的隔离模拟；真实 Provider 卡包元数据已单独只读核验，手机微信原生 `openCard`、真实微信/支付宝扣款和授权回跳留作发布后的真人验收。没有在真实客户订单上发起付款或重开票。
