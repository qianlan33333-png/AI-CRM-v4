# Referral / Distribution / Order-Payment 审查

基线为 `94d4b845f9d9ddcc30e7e05432032ba1677fac5a`。先读仓库 `AGENTS.md`、`docs/development-before-start.md` 与 `skills/aicrm-v3-development*/SKILL.md`。业务源按只读审查；之后按主线授权，仅在 `internal/referral/app/admin.go` 增加到期保护，并新增一个 PostgreSQL 回归测试。未调用生产、Provider、消息、支付、退款、分账或提现接口。

**最高发现为已修复的 P2 生命周期完整性问题，无已确认的佣金金额或安全高危问题。** Campaign 的 `EffectiveState` 和 `AcceptingAt` 将结束时刻定义为半开区间 `[StartsAt, EndsAt)`；即使关闭任务延迟，`EndsAt` 到达后对外状态已经是 `ended`（`internal/referral/domain/referral.go:163-182`）。但旧的 `SetCampaignState` 只按持久状态迁移，仍允许过期的持久 `active` 活动转成 `disabled`；关闭任务随后因 `disabled` 直接退出、不写排名快照（`internal/referral/app/admin.go:170-224,433-481`）。基线 PG 实测输出为 `expired campaign state="disabled" close_snapshots=0`，见 [基线证据](/Users/qianlan/Documents/Codex/2026-10-04/task/referral-expiry-baseline.txt)。最小修复是在行锁后拒绝 `now >= EndsAt` 的状态变更，让原 River close job 负责结束与快照；到期前停用仍允许。新 PG 用例验证到期后命令返回 conflict、worker 写入 `ended` 和一条快照，同时断言到期前仍可停用，见 [回归证据](/Users/qianlan/Documents/Codex/2026-10-04/task/referral-expiry-regression.txt) 与 [回归测试](/Users/qianlan/Documents/Codex/2026-10-04/task/AI-CRM-v4/internal/referral/app/expired_state_postgres_integration_test.go:13)。修复点在 [admin.go](/Users/qianlan/Documents/Codex/2026-10-04/task/AI-CRM-v4/internal/referral/app/admin.go:192)。

实际入口和所有权：Referral 公共入口是 `/api/v1/referral/*`、邀请/活动 handoff `/referral/invite/*`、`/referral/activity/*`；活动创建、状态、战队、参加撤销、邀请撤销、奖励写入由 `/api/admin/referral/*` 管理。分销公共入口为 `/api/v1/distribution/*` 和 `/d/{credential}`，后台为 `/api/admin/distribution/*`（`internal/referral/http/handler.go:124-205`、`internal/distribution/http/handler.go:106-137`、`internal/distribution/http/admin.go:44-85`）。两者公共会话从已验证的 Payment 会话桥接；Referral 写请求走同源/CSRF，后台仅 Admin/SuperAdmin 可写、Viewer 可读；Distribution 复用 Access 员工会话，同样区分读写角色并对写入执行 CSRF（`internal/referral/http/handler.go:599-615,1736-1749`；`internal/distribution/http/admin.go:441-479`）。

Referral 拥有 campaign、参加/邀请关系、积分、奖励、产品活动 checkout 与销售 credit/reversal 账本；Distribution 拥有分销员、推广凭证、下单时冻结的归因、佣金、结算及异常；Order/Payment 分别拥有订单/退款事实和资金/provider 效果。一级分销是明确能力边界：PRD 明示不做二级分销、不改变客户归属，归因表只冻结一个 `distributor_id`，没有下线层级（`docs/prd/2026-09-14-first-level-distribution.md:5-13,35-50`；`migrations/0157_distribution_core.sql:97-123`）。裂变关系不参与分销佣金归属：佣金归属来自 Distribution 凭证和冻结的订单归因；销售榜则按付款时活动状态及冻结归因记录个人/当时有效战队销售（`internal/referral/app/order_events.go:130-202`、`internal/referral/app/sale_campaign.go:13-42`）。

金额和回退：Order 当前 checkout 构造一条商品项，`LineAmountMinor` 与本次优惠后应付一致（`internal/order/app/service.go:302-348`）。佣金采用商品项实付分乘冻结基点向下取整，限 0–3000 基点、人民币，不把运费或客户端佣金参数带入；成功退款后以 Payment 累计退款重算未提交佣金，已提交/已到账仍保留原分账事实并进入异常处理（`internal/distribution/domain/distribution.go:222-261,264-299`、`internal/distribution/app/commission.go:95-172`、`internal/distribution/app/refund.go:199-285`）。Referral 销售退款写负向追加事件；重复收据不重复记账，累计反冲封顶于原销售额，全额反冲才减订单数（`internal/referral/app/product_sales.go:172-227`）。

事务、重放和异步：下单与 Distribution 归因、Referral checkout 快照处于同一 Order UoW（`internal/order/app/service.go:322-348`）；首次支付事件在 Order 结算 UoW 内顺序 fanout 到 Distribution/Referral，任一错误使该事务回滚（`cmd/aicrm/order_paid_event_fanout.go:21-39`、`internal/order/app/service.go:1098-1148,1172-1197`）。确认退款后，Order fanout 到 Referral 追加反冲并在 Distribution 原子入队退款复核（`cmd/aicrm/order_refund_settlement_fanout.go:16-25`、`internal/distribution/app/refund.go:57-87`）。River 任务包括 Referral campaign 结束快照、Distribution 佣金到期检查和退款复核，使用事务内入队与唯一参数约束（`internal/referral/app/campaign_river.go:14-44`、`internal/distribution/app/settlement_river.go:35-45,79-118`）。参加唯一约束为 `(campaign_id, customer_id)`；邀请加入锁住参与者和邀请人，确认邀请仍有效且邀请人 active；同一操作收据精确重放不重复积分（`internal/referral/app/service.go:268-409`、`migrations/0185_referral_core.sql:63-78,112-130`）。订单归因唯一于订单项，佣金唯一于 attribution；分销售后按全局顺序锁佣金行、CAS 版本、将人工追回/承担与累计可处理差额比较（`migrations/0157_distribution_core.sql:112-140`、`internal/distribution/store/commission.go:106-129`、`internal/distribution/store/settlement.go:279-327`）。

**低风险重放契约项：** `POST /api/v1/referral/campaigns/{id}/product-context` 要求 `Idempotency-Key`，但 `IssueProductActivityContext` 只校验后丢弃该 key，每次生成新随机 context 并写一行（`internal/referral/http/handler.go:345-364`、`internal/referral/app/service.go:72-110`）。客户端重试会多造短期、到活动结束失效的 context 行；目前未发现它能重复下单记佣或影响资金。可后续统一：要么将相同 key 绑定同一个 context receipt，要么去掉该入口的幂等语义要求。此项不纳入本次窄修复。
