# AI 修改裂变海报二维码布局

本能力首次发布后，活动海报坐标存于数据库。日常调整直接调用管理员 API，无须改源码、构建、重启或再次发布。后台不提供坐标编辑控件。每张图独立绑定图片、说明、话术和二维码布局。

## 默认制图规格

原图 **1250×2426 px**。二维码白色方框左上角 **x=810、y=1932**，边长 **370 px**，距右70、距底124。坐标原点是原图左上角，单位是原图像素，与手机预览的 CSS 尺寸无关。

新图使用默认规格时，直接沿用后台最多三张的上传/发布流程。使用其它尺寸的活动图时，AI 在已有 `PUT /api/admin/referral/campaigns/{id}/posters` 的对应项一并提供 `qr_layout: {"x":810,"y":1932,"size":370}`，坐标须适合实际原图；继续沿用原有图片大小及尺寸边界。省略布局的新图要求默认1250×2426规格。旧已发布图片保留原尺寸及兼容布局。

## 读、改、再读

复用正常管理员登录会话及现有 CSRF：Cookie 中的 `aicrm_admin_session`、`aicrm_admin_csrf`（兼容镜像为 `aicrm_csrf`），写入请求带 `Origin`、`X-CSRF-Token` 和 `Idempotency-Key`。Cookie/令牌通过受保护会话或凭据渠道提供，不写进源码、文档、测试收据或日志。生产与预发使用各自授权会话。

1. `GET /api/admin/referral/campaigns/{id}`。确认活动身份、当前 `version`，读取 `posters[].slot/image_id/image_width/image_height/qr_layout/share_text`。
2. 根据新图的二维码留白位置，发送 **`PUT /api/admin/referral/campaigns/{id}/poster-layouts`**。可以只改一张，也可以同时改三张。下例版本12只作请求形状说明，实际须使用刚读到的版本：

```json
{
  "expected_version": 12,
  "posters": [
    {"slot": 1, "x": 830, "y": 1952, "size": 330},
    {"slot": 2, "x": 810, "y": 1932, "size": 370},
    {"slot": 3, "x": 830, "y": 1952, "size": 330}
  ]
}
```

3. 成功返回 `{campaign_id, version, posters}`。再次 GET 活动，确认版本和目标 slot 的三个数已保存；未提交的海报、图片、话术和说明应保持原值。
4. 在已有参与用户会话中关闭并重新打开「生成溯源码」，读取最新布局并合成 PNG。长按保存/下载的 PNG 保持原图尺寸、包含该用户专属邀请二维码；布局不替换二维码内容。解码保存的 PNG，核对当前用户邀请链接。

接口只修改当前已发布海报的布局，不重新读取素材库原图；即使素材随后停用，已冻结海报仍能调整。后台保存会保留已读到的布局；旧页面的过期版本写入会被拒绝。

## 数值与错误

| 字段 | 含义 |
| --- | --- |
| slot | 当前海报序号1–3，须存在；删除后按当前 GET 的序号定位 |
| x、y | 白色二维码方框左上角，非负整数，两个字段必须显式提供，0有效 |
| size | 正整数，白色方框边长；x+size≤原图宽、y+size≤原图高 |

二维码实际黑色模块居于白框内，保留至少四模块白边，使用整数像素以保持清晰。不要按黑色码的外框测量白色方框；原图自带码时，应完整覆盖原有码区。码框过小而无法绘制时页面明确报错，不生成假成功图片。

- `400 invalid_request`：缺字段、非整数、越界、重复/不存在slot；整组不写入。
- `409 conflict`：版本过期；重新 GET 核对后以新版本和新的操作键提交，不自动覆盖他人修改。
- `409 idempotency_conflict`：同一操作键换了请求内容。网络结果不明时先用**同键、同请求**重放并读回；确定新操作才换键。
- `409 campaign_config_locked`：已结束/停用活动沿用现有配置锁定规则。
- `401/403`：登录或管理员权限/CSRF未通过；复用正常鉴权流程。

成功重放不再次改版本。布局、版本、收据、审计和 Outbox 在同一 PostgreSQL 事务提交或回滚；没有 Provider 写入或新增后台任务。

## 专属海报昵称

`POST /api/v1/referral/campaigns/{id}/invite` 沿用原鉴权、CSRF和幂等键，响应包含 `url`、`expires_at`，可选新增 `poster_nickname`。昵称来自该次签发已验证 OneID 根的可信微信 OAuth 投影；缺失或读取失败时省略，不回退到运营展示名，不公开客户 ID。前端将昵称单行写入海报右上角，约30px常规字体、米白色、48px安全边距，超长按完整字素省略。二维码内容及活动归因保持原机制。

默认规格变更仅影响未指定坐标的新海报。既有持久化坐标继续有效；当前活动5的slot1须在获得生产配置授权后经上述API单独改为 `{x:810,y:1932,size:370}` 并读回，不能把应用安装称为该配置已经调整。
