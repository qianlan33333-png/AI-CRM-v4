# 群邀请直接入群码与下载入口修复

状态：已确认冻结。用户在 2026-09-23 指出当前下载码先进入 `/gi/` 页面，要求减少一次跳转，并明确选择将生产旧计划升级为固定企微码。

## 1. 业务判断

- 运营人员复制的 `/gi/{token}` 是 CRM 固定公开页，下载按钮当前生成的 GIF 也编码该 URL；扫码 GIF 后才出现公开页中的企微入群码。附件 `邀请入口-11 (2).gif` 解码结果与生产计划 11 的 `join_url` 完全相同。
- 公开页中的官方二维码扫码得到 `https://work.weixin.qq.com/gm/{config_id}`。当前例子可从用户截图解码，但企微 `get_join_way` 的正式响应只给 `qr_code` 图片 URL 和 `config_id`，不承诺可按 `config_id` 拼出、长期分发一个网页 URL。不得把观察到的 URL 规律当 API 合同。
- 用户目标：下载按钮获得图二中的**企微官方二维码图片**，用户扫码后直接进入企微入群流程；多群切换后同一张已分发图片仍能承接新群，才可称为固定入群码。
- 生产计划 11 是旧的按群分别生成 `config_id` 的记录，现无 `media_invitation_join_ways` 行。直接下载它的当前群码会在切群后仍指向旧配置。v4 的新计划实现采用一个 `config_id` 原地更新绑定群；旧计划若要固定官方码，须先完成受控升级和真实企微读回。

## 3. 复用与架构分类

- 现有入口：`/admin/group-invitations` 的 admin 单壳、`admin_invitations.js`、`/api/admin/group-invitations`；公开 `/gi/{token}`；Media 的计划与 join-way Owner；Outbound/EER 的企微写入。
- OneID：不涉及。只管理群计划、群 ID 和公开入群方式，不匹配客户身份或变更归属。
- Persistence：按钮下载是认证读取与外部图片读取；旧计划升级涉及 Media 本地事务、Outbound Provider 写入/外部效果与持久任务，须沿用现有 EER，不新建队列或状态机。
- 前端沿用原列表按钮、状态和通知样式，不引入新组件。Product Design 按既有页面的体验缺陷审查；CRM 模板只作为现有视觉基线。

## 4. 产品合同

1. “复制链接”继续提供已公布的 `/gi/{token}`，作为公开状态页与故障兜底；不从 `config_id` 猜测企微直达 URL。
2. “下载入口码”在**同一企微配置已执行并读回**时下载该配置的官方二维码图片。二维码扫码直接进入企微群，不再先访问 CRM `/gi/`。
3. 未生成、待执行、结果未知、已暂停、群资料过期、群池满或二维码 URL 缺失时，按钮不下载旧码，明确显示对应状态。下载失败要提示，不能把打开图片或假成功当下载完成。
4. 旧生产计划须先接管或新建单一企微 `config_id`，确认官方二维码与当前群、`auto_create_room=0`、可重复读回一致，再开放固定码下载；旧二维码和既有 `/gi/` 链接保留直至运营切换。若无法安全接管，明确新码更换及重新分发边界。
5. 旧计划升级等待新配置时，既有 `/gi/` 页继续展示当前旧群码；新官方下载保持关闭。日后同一企微配置切群时，更新完成前公开状态为准备中；成功读回同一 `config_id`、同一官方二维码和新群绑定后才恢复可下载/可扫码。`outcome_unknown` 只对账，不盲目重试。

## 5. 技术边界和验收

- 管理端通过认证的 Media API 获取可下载的官方二维码；服务端校验计划状态、Provider receipt、二维码 URL 主机、响应类型与大小，采用同源受控下载响应，避免跨域 `download` 属性失效和任意 URL 代理。不得将企微凭证或群二维码原始内容写入日志。
- 旧计划迁移只能在 Media Owner 的事务内登记意图与审计，由 Outbound 执行 Provider 写入；不得修改生产计划数据来模拟成功。
- 验收：新计划和旧计划的按钮状态；下载图片扫码直接到企微；与旧 GIF 解码结果不同；同一固定二维码切群后仍进入新群；Provider 失败/未知结果阻止旧码误发；403、缺码、坏图片、跨域与大文件失败；生产当前计划 11 的真实企微读回和测试微信扫码独立记录。
- 对每项记录准确 v4 commit/tree、本地测试、staging 虚拟 Provider 验收、生产 Provider 回执、真实扫码。虚拟验收不能冒称真实企微成功。
