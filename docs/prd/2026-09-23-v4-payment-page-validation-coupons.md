# V4 支付页与支付完成页设计 PRD（已确认，补充优惠券）

日期：2026-09-23。初始代码基线：`AI-CRM-v4` `main`，`f07d76f2b1e3585bf930f5e9a2a37fe5bf87baaa`；实现已更新到 PR #20 合并后的 `main` `5d15f9691e73ce81f3017f5379fc668b2e80a9fe`。设计稿为示意，渠道码图片不可扫码。

## 1. 业务判断

1. 只有商品配置要求的信息才是必填。未收集信息时无需提示；收手机号时校验手机号；收收件信息时校验省、市、区、收件人、详细地址和手机号。缺失时不得创建订单或调起支付。
2. 点击“立即支付”后，按钮必须即时给出反馈；缺失字段在对应控件附近标红，按钮附近汇总具体缺失项。补齐后清除相应错误。原有订单恢复路径优先于重新下单。
3. “收货信息”标题旁用小号红字“收实物商品使用”，只在收收件信息时出现。
4. 确认订单页与支付完成页的商品区只展示文字商品信息；不展示头图、缩略图、商品备注或订单备注。商品描述仅在原商品数据存在时展示，不新增字段。
5. 仅在服务端确认订单已支付后显示“支付完成”。购买后动作以该订单冻结的 `completion_action` 为准：启用且可用的二维码在一级页面直接展示；配置为跳转则沿用跳转；未启用则只展示完成状态；二维码不可用时显示现有失败提示。不得从当前商品配置重新推算历史订单的动作。
6. 普通商品与周期商品遵循同一规则；周期商品保留现有续费与已购恢复语义。微信和支付宝使用同一支付完成展示合同。支付宝入口由已合并的 V4 PR #20 纳入当前 `main`，仍需按当前候选完成独立验收。

## 3. 页面与状态

### 确认订单页

- 商品：名称、已有描述、现有价格与周期信息（若适用），纯文字；不渲染商品图片及备注。
- 收货配置为 `none`：无收货卡、无手机号卡。
- `mobile`：手机号必填，错误示例“请填写手机号”“请输入正确的大陆 11 位手机号”。
- `shipping_address`：收货卡标题旁“收实物商品使用”；省、市、区、收件人、详细地址、手机号均必填。错误例“请选择省”“请选择市”“请选择区/县”“请填写收件人”“请填写详细地址”“请填写手机号”。底部汇总可合并为“请填写详细地址、手机号”；多个错误按页面顺序排列，不只给“请完整填写收货信息”。
- 点击支付按钮时立即显示按压或短暂加载反馈，验证失败后恢复可点状态、定位首个错误，不发创建订单请求；验证通过再沿用当前结账、支付、恢复流程。重复点击不得绕过当前幂等键。

### 支付完成页

- 仅 `paid` 显示绿色完成标记与“支付完成”；商品名称及已有描述为纯文字。价格若后端返回可信的订单实付金额则显示；缺失时不拿当前商品标价冒充订单实付。
- `completion_action.state=available, mode=qr` 且 `lead_qr.url` 有效：一级页面直接显示冻结的标题、二维码图片及副标题，无弹窗、无二次点击。
- `available, mode=redirect`：沿用现有跳转；跳转失败保持已支付订单恢复能力。
- `state=none` 或未配置：完成页不出现渠道码；`unavailable`：显示后续指引暂不可用，不伪造二维码。
- 二维码加载失败显示现有刷新提示；刷新只读取原订单，不重新支付。

## 5. 边界与风险

- OneID：本次只用现有授权购买身份，不新增身份解析、建客或归属规则。
- Persistence：支付和订单已有持久化及幂等；本次只改变前端验证和展示，不新增持久任务或数据写模型。
- External Effects：不新增 Provider 写入；支付调用只在通过验证后复用现有流程。支付状态未知时保留原订单并只读恢复，禁止再次建单。
- 数据 Owner：商品配置归 product，支付订单及冻结动作归 payment。展示层仅读取既有 API。
- 红线：未经支付确认显示成功、重复支付、展示别的订单渠道码或泄露收货 PII 均为阻断条件。

## 8. 优惠券补充（用户确认的范围）

- 付款页单独展示优惠券卡片：当前已领取的适用券从既有 `GET /api/h5/coupons/available?target_ref=...` 读取，可选某张或沿用自动最优；展示预计优惠与预计实付，创建订单后的真实金额仍以 Payment Owner 返回为准。
- 现有领券能力在 `/c/{public_slug}`，由带可信付款会话的公开券页执行有幂等键的领取。付款页没有可领券发现接口，本次不伪造领券列表，也不新增 Coupon Owner 写入口。用户从现有券分享链接领券后返回付款页，可点“刷新优惠券”重新读取。
- 无已领取适用券：文案“暂无可用优惠券”；读取失败：保留已展示状态并提示重试；原订单 checkpoint 存在：券选择和刷新均锁定，金额显示原订单返回值或“待确认”，不重新估价或重建订单。
- OneID：Coupon Owner 从既有可信 session 获得 canonical holder，本页不解析或传入客户 ID。Persistence：本页 stateless；领券事务仍由 Coupon Owner 负责。External Effects：无新增。
- 验收：无券、有券/自动最优、手选、领券后刷新、过期/不适用券、读取失败、原订单锁券与服务器金额，覆盖普通/周期商品及已支持的支付方式。
